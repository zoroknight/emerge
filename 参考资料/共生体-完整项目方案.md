## 1. 项目定位

### 1.1 一句话介绍

在架空的原始海洋中，玩家控制能够同化其他细胞的核心生命，通过排列、旋转、连接和布线，让只遵循简单规则的细胞共同产生运动、摄食与生存能力，最终抵达热泉圣所。

### 1.2 基本设定

| 项目 | 当前方案 |
| --- | --- |
| 暂定名 | 共生体 / Symbiosis；工程目录名 emerge |
| 类型 | 2D 生存探索 + 生物构筑 + 物理涌现 |
| 视角 | 侧视，XY 平面自由游动 |
| 平台 | PC；首个打包目标建议为 Windows，具体提交要求待确认 |
| 技术方向 | Unity 6 + C# + URP 2D；具体已安装版本待开工时核实 |
| 开发条件 | 20 天，单人，AI 辅助 |
| 单局目标 | 整合建议：首个可通关版本约 10～15 分钟；原始愿景为 20～30 分钟，按内容和试玩结果调整 |
| 胜利条件 | 核心存活并抵达热泉圣所的终点区域 |
| 失败条件 | 核心完整度耗尽；能量不足首先使执行器停工，再通过生存系统导致损伤 |

背景不绑定真实地球年代。环境与生命规则服务于玩法，不追求完整生物学模拟。

### 1.3 四个必须成立的体验

1. 调整身体的位置、朝向或线路，能明显改变操作结果。
2. 简单规则组合后，出现单个成员没有的功能。
3. 细胞融合后形成一只完整、可爱的生命，并仍能读懂它的功能。
4. 摄食和活动形成闭环后，玩家能清楚感到共生体从勉强运行进入稳定运行。

这四项比地图数量、细胞数量和框架完整度更重要。

## 2. 玩家体验与完整流程

### 2.1 核心循环

```text
探索 → 获取营养 / 发现细胞 → 同化 → 重组身体与线路
  ↑                                           ↓
进入新环境 ← 验证生存能力 ← 运动 / 摄食等功能产生
```

玩家始终参与移动、同化和身体调整。探索提供新的底层规则，环境提供需要解决的问题。

### 2.2 一局的体验阶段

| 阶段 | 玩家主要行为 | 希望发生的体验 |
| --- | --- | --- |
| 出生 | 熟悉核心、短距离移动和营养 | “这是我的小生命。” |
| 初次构筑 | 同化纤毛、旋转并连接信号 | “换个位置，操作就变了。” |
| 首次协同 | 获取吸收细胞，将食物流路带到吸收面 | “两个简单东西一起能主动吃到食物。” |
| 环境筛选 | 调整形状、推力、保温或路线 | “我能用自己的方案穿过去。” |
| 闭环启动 | 提高摄食效率，使能量持续供给动作 | “它开始稳定地活着了。” |
| 抵达圣所 | 穿过最后的环境压力，进入稳定水域 | 释放紧张感，展示玩家最终身体 |

### 2.3 开局防卡死方案

旧资料同时存在“只有一个核心”和“初始身体符合传统 WASD”两种描述。

**整合建议：**核心出生在一个安全小湾，周围有可立即同化的纤毛和营养。核心保留极弱的基础摄食与漂移能力，只够完成首次同化；若试玩表明仍难理解，改为提供一个可拆解的最小初始身体。强移动能力仍必须来自纤毛与结构。

首分钟不设置持续致命压力。用局部提示解释输入、旋转、布线和同化；不直接展示器官配方。

## 3. Jam 范围与优先级

完整设计目标与最低可交付范围分开管理。以下缩减范围属于**整合建议**，不是原资料已经确认的变更。

| 内容 | 完整设计目标 | 最低可交付范围 |
| --- | --- | --- |
| 细胞 | 核心 + 六种功能细胞 | 核心、纤毛、吸收、膜；收缩视物理验证结果加入 |
| 地图 | 五种区域主题，连续海域 | 一张手工地图，安全区、挑战区、圣所三段 |
| 涌现 | 推进、转向、滤食、导流、形变等 | 至少三种经过对照验证的结构效果，其中包含跨细胞协同 |
| 信号 | WASD 四通道、线路与衰减 | 四通道、线路、执行器反馈；传导远端优势属于扩展 |
| 生存 | 营养、能量、温度、完整度 | 四项保留，先用全身共享值 |
| NPC | 5～7 种不同身体结构 | 1 种示范生命 + 1 种危险生命 |
| 封装 | 稳定连通子图整体编辑、视觉融合 | 可选的分组移动与旋转；若拖慢交付则延期 |
| 视觉融合 | 连续生命膜与功能暴露 | 果冻连接桥、弱化独立边界、保留功能特征 |
| 结局 | 圣所中的生命延续表现 | 抵达、身体展示、胜利反馈、重新开始 |

### 3.1 优先级

- **P0，必须交付：**可编辑身体、信号控制、推力与转矩、营养摄食、能量闭环、温度与损伤基础规则、至少三种结构效果、完整起终点、基础教学、音画反馈和可运行包。
- **P1，核心验证通过后做：**收缩、感知信息、传导优势、完整五区域、分组封装、更多 NPC、更自然的身体融合。
- **P2，时间充足才做：**复杂融合着色、可保存身体方案、额外环境变化、幼体结局动画。

### 3.2 首版明确不做

真实流体、复杂软体求解、遗传算法、技能树、完整进化、自动神经网络、周期控制信号、Boss、程序生成地图、剧情对话、多人和大量敌人种类。

持久化存档不作为首版必须项；重新开始与关卡内恢复属于交付功能。赛事要求若另有规定，再调整范围。

## 4. 细胞、身体与连接

### 4.1 七种细胞的规则

| 细胞 | 基础规则 | 主要可调参数 | 功能视觉 |
| --- | --- | --- | --- |
| 核心 | 同化、代谢、产生四种意图信号；整合建议保留极弱基础摄食 | 代谢上限、资源容量、连接上限 | 圆润团子、柔和星点 |
| 纤毛 | 沿功能方向推动附近介质，自身承受对应反作用 | 推力、影响距离、活动耗能、方向 | 一侧 3～5 根软尾毛 |
| 收缩 | 收到持续信号后缩短指定连接，释放后回到原长 | 目标长度、响应速度、耗能 | 弹簧豆或柔软条纹 |
| 吸收 | 接触营养时高效摄食 | 接触范围、吸收速率 | 花瓣状开口 |
| 膜 | 对局部物质通行和热交换产生阻碍，提高稳定性 | 阻挡范围、保温、质量、阻力 | 圆润壳片 |
| 感知 | 揭示附近环境信息，首版不产生自主控制信号 | 感知距离、信息类型 | 小触角、提示波纹 |
| 传导 | 降低经过自身的意图信号衰减 | 传输效率、连接上限 | 珠子、内部光线 |

参数用数据资源管理。以上不预设具体数值；数值必须由 Cell Lab 及完整试玩确定。

### 4.2 身体是图结构

细胞为节点，融合连接为边。每个节点至少记录类型、位置、旋转、功能朝向、完整度、连接上限和所属共生体。

每条连接记录两端节点、锚点、原始长度与连接强度。只有主核心直连的连接保存一个 W/A/S/D 出口通道；其他连接自动传递上游信号，不配置通道或损耗。

### 4.3 自由圆周连接

采用连续圆周接触位置，取消固定六向融合点。编辑时提供可关闭的角度软吸附。

整合建议的初始约束：普通细胞最大连接数 3～4，核心更高；首次原型以 20～30 个细胞作为压力测试规模，不等于最终玩家上限。

有效连接需满足距离、连接数、重叠与图连通约束。拆除桥接细胞后，失去核心连接的组织转为漂浮细胞或漂浮碎片，不能继续接受核心控制。

### 4.4 旋转与功能方向

功能方向固定在细胞局部空间，世界方向随细胞旋转改变。纤毛的推水方向与身体获得的反作用力方向应在编辑预览中分开标示，避免玩家把两者混淆。

玩家调整朝向；执行器不自动寻找最佳方向。整体转动以后，原线路仍激活原执行器，因此控制结果可能改变。

## 5. 输入、信号与重组操作

### 5.1 四个持续意图通道

W、A、S、D 只是通道 0～3，不天然对应世界方向。按住时激活，释放后停止。玩家可以将同一通道连接到多个执行器。

示例：W 用于主推进，A/D 用于不同位置的纤毛转向，S 用于摄食结构。示例用于开发验证，不做玩家配方列表。

### 5.2 线路传播

**已定方向（2026-10-02 用户确认）：**只在主核心直连的连接上配置 W/A/S/D，每条出口选择一个通道；后续连接与细胞自动接收、响应和转发相同信号。纤毛没有自己的 WASD 设置，功能方向仍固定在局部空间。

损耗从核心输出向后逐层计算，不由玩家配置连接损耗。当前核心输出 1，普通节点保留 90%，第一层为 0.9、第二层为 0.81；传导节点衰减较小。执行器强度取已接收通道中的最大有效强度，并受能量供给限制；同时按多个键不把强度无限累加。

图中可能有环，按通道求各节点的最强可达信号，重复路径不叠加放大。信号从选定的核心出口注入，不返回核心再串入其他出口；下游分支若直接互连，则自动转发收到的原信号。编辑图改变时刷新传播关系，物理运行时只更新输入与活动状态。

首版不做真实神经传播延迟。光点沿线运动是视觉反馈，不能让视觉上的周期动画变成未定义的周期控制机制。

### 5.3 感知与节律的冲突处理

已定方向是取消额外周期信号、保留 WASD 四种持续通道。为保持一致，采用以下**整合建议**：

- 感知细胞首版提供附近资源、危险或环境信息，不直接激活执行器。
- 收缩在按住时缩短、释放时复原；反复按键可以形成手动往复动作。
- 自动逃避反射、自动搏动泵、传播延迟波浪列入后续扩展，不能写入首版验收承诺。
- 身体呼吸、纤毛摆动和音乐节拍可持续播放，但属于表现层。

如果以后决定加入自主反射，需要单独定义环境信号源、路由、优先级和耗能规则，并修订“只有四个玩家意图源”的范围。

### 5.4 操作草案

下表为整合建议，具体按键通过试玩调整。

| 输入 | 行为 |
| --- | --- |
| WASD | 激活对应通道 |
| Tab | 切换游动 / 重组模式 |
| E 长按 | 同化接触中的自由细胞 |
| 鼠标左键 | 选择；重组中拖拽 |
| Q / R | 重组中旋转选中细胞 |
| 界面按钮 | 连接 / 拆连接、核心出口信号选择、分组 / 解组 |
| Esc | 暂停与返回菜单 |

### 5.5 重组模式

已定方向是重组时世界大幅减速。整合建议先以暂停式编辑完成原型，操作稳定后再验证减速编辑的压力是否合理。

重组步骤：选择细胞 → 移动或旋转 → 建立连接 → 选择核心出口信号通道 → 预览激活节点、合力和转矩 → 回到游动验证。

编辑期间不通过瞬移身体获取推进、不在无限暂停中生成营养、不无成本反复完成同化。修改结构后清理过期连接与物理状态，避免退出编辑时积累冲量。

## 6. 运动、流场与涌现

### 6.1 两类作用明确分开

纤毛与环境交换动量，产生外部推进；收缩改变内部结构。收缩不直接为整个共生体额外添加平移力。

同一纤毛的受力方向决定平移趋势，施力位置相对身体质心的偏移决定转矩。两侧对称推进可以减少偏航，偏置推进可以转向。

### 6.2 物理方案与止损

首选方案：每个细胞一个 Rigidbody2D、碰撞体和必要的 Joint。收缩修改指定连接的目标长度；连接负责传递受力。

Day 2～3 必须测试多节点、环、长链、持续驱动及强流中的稳定性。若出现持续抖动、穿透或连接发散，切换为整个共生体一个刚体，在各纤毛位置施力。

**切换的影响必须明确：**单刚体能保留推进与转矩，但不能直接保留真实柔性收缩。此时收缩改为有限的局部虚拟形变，若成本仍过高则从交付范围移除。不能宣称两种方案提供完全相同的玩法。

### 6.3 流场方案

```text
局部流速 = 环境流场 + 附近已激活纤毛的流场贡献
```

环境通过位置查询流速；纤毛提供带方向、范围与衰减的局部流场。营养颗粒随局部流速移动，身体受环境流与自身速度差产生的作用影响。

不做完整流体求解。膜细胞若要产生真实可用的导流，必须至少影响营养轨迹或局部流场查询。仅提高防护值与画一堵墙，不能验收为“膜导流”。

简化方案优先让膜阻挡营养颗粒，并在局部障碍附近调整流动方向；需要在原型中验证是否能形成可读的流路。

### 6.4 旋流摄食的修正

V0.2 提出切向纤毛形成旋流并将营养带向中心。实现上不能仅画环形流线就认定摄食成立：**纯环绕轨迹可能让颗粒持续绕行，未进入吸收接触区。**

待验证方案：让纤毛朝向略微内倾、调整吸收面位置，或用膜与缺口建立经过吸收区的路径。必须看到实际营养颗粒进入吸收区，并测得净摄食收益。

若旋流方案不能稳定成立，首先交付定向滤食：纤毛建立经过吸收面的流路。这仍符合关系产生能力的主题。

### 6.5 内部组合验证表

| 组合 | 期待结果 | 验收依据 | 优先级 |
| --- | --- | --- | --- |
| 纤毛 + 位置关系 | 推进 / 转向 | 相同细胞数量，改变布局后轨迹明显不同 | P0 |
| 纤毛 + 吸收 | 主动滤食 | 与吸收单独使用相比，摄食收益提高且能覆盖增加的耗能 | P0 |
| 膜 + 吸收 | 捕食袋 / 留存 | 颗粒被实际留在可吸收区域；不能只加一个吸收倍率 | P0 候选 |
| 纤毛 + 膜 + 吸收 | 导流摄食 | 膜改变颗粒路径，使更多食物经过吸收面 | P0 候选 |
| 收缩 + 纤毛 | 可控转向或推进方式改变 | 收缩改变功能朝向，实际运动随之改变 | P1 |
| 收缩 + 膜 | 手动腔体动作 | 往复改变腔体并产生实际颗粒输送；失败则不称为泵 | P1 待验证 |
| 传导 + 远端执行器 | 远距离协调 | 相同路径长度下远端信号更强、更稳定 | P1 |

至少三种结构效果需要实测，其中必须有不同细胞类型之间的协同。平移与转向的两张截图不能代替全部涌现验证。

## 7. 资源、生存与系统启动

### 7.1 四项共享状态

| 状态 | 来源 / 变化 | 对玩法的作用 |
| --- | --- | --- |
| 营养 Nutrient | 核心基础摄食、吸收细胞高效摄食；代谢消耗 | 能量原料 |
| 能量 Energy | 核心代谢产生；执行器和维持活动消耗 | 决定动作能否持续 |
| 温度 Temperature | 代谢产热、环境交换、流动与膜影响 | 低温降低效率，过热导致损伤 |
| 完整度 Integrity | 碰撞、捕食和环境应力损伤 | 细胞脱落与核心死亡 |

**整合建议：**营养、能量和温度先使用全身共享值，不实现逐边运输与内部循环网络。细胞保存局部完整度，界面显示整体状态并突出核心危险。

资源运输、氧气与真实循环系统属于扩展。首版不能将共享能量池描述成玩家已经构造出的循环器官。

### 7.2 最小资源闭环

```text
营养颗粒 → 吸收 → 营养储备 → 核心代谢 → 能量 + 热
                ↑                         ↓
                └── 更有效摄食 ← 水流 / 运动 ← 执行器
```

启动来自实际收益和活动连续性，不由某种固定细胞配方触发。

### 7.3 能量与活动

活动需要有效信号和可用能量。能量不足时，按供给比例平滑降低执行器输出，避免在临界值上每帧开关。

整合建议先按所有执行器的需求总量统一分配供给比例，避免节点更新顺序决定谁抢到能量。代谢有速率上限，摄食和资源存量有容量限制，防止无限增长。

能量长期不足时，先停止高耗能活动，再发生饥饿损伤；不能按一次耗尽就立即判负。核心的基础维持能力为玩家提供短暂恢复机会。

### 7.4 温度与膜的代价

代谢产热，环境造成热交换。膜降低局部或整体散热，同时增加质量、阻力或阻挡摄食接触面。

保温在寒冷中有利，在高代谢时也可能增加过热风险。低温、适温、过热阈值和效率曲线全部通过试玩调整。

强流不应仅凭“处于某区域”持续扣血：至少与速度差、碰撞或连接负荷建立关系，让结构与路线真的影响损伤。

### 7.5 “系统启动”的识别与反馈

整合建议以一个短时间窗口统计净能量收益、能量储备和执行器实际供给比例。持续满足健康运行条件后进入启动表现，退出条件稍宽，避免闪烁。

启动反馈：核心更稳定地发光、纤毛活动连续、营养流路更明显、身体光纹逐段点亮、音效与音乐进入节奏。反馈只反映真实运行状态，不额外赠送输出倍率。

启动不要求无限加速。目标是从缺能导致的断续活动转为稳定满负荷；更大的身体与更强代谢是否构成进一步正反馈，留给实测。

## 8. 同化与封装

### 8.1 同化

营养自动摄食；自由细胞需要主动同化。

流程：靠近有效接触位置 → 长按同化 → 显示临时连接与进度 → 持续接触并消耗能量 → 成为身体节点。

能量不足、接触断开或受到明显撞击会中断。新增节点后更新连接图、线路、质量与视觉。

整合建议首版不做背包：获得细胞即接入身体，重组时调整。脱落细胞可重新同化；核心不能同化第二个核心成为多核心身体。

### 8.2 封装

选中连通子图后，将它作为编辑分组整体移动和旋转，保留内部细胞规则及线路。可以解组重新编辑。

封装不自动获得器官技能，不自动提高摄食或推力。首版建议只减少操作复杂度与视觉割裂；内部连接强化若加入，必须明示其幅度及代价。

封装是 P1。连续身体视觉可以由普通融合直接提供，避免“未实现封装就无法看起来像生命”的依赖。

## 9. 世界、关卡与其他生命

### 9.1 五个区域的完整目标

| 区域 | 空间与视觉 | 主要压力 | 允许的解决方向 |
| --- | --- | --- | --- |
| 原初浅湾 | 开阔、青绿、柔和光柱 | 学会运动与摄食 | 调整纤毛、建立吸收流路 |
| 菌柱森林 | 圆润菌柱、紫蓝植物、窄缝 | 身体尺寸与操控精度 | 缩小、拉长、减速、绕路 |
| 裂谷急流 | 狭长通道、落差、蓝色流线 | 强流、偏航、结构负荷 | 提高定向推力、平衡转矩、借流、绕行 |
| 黑潮洞穴 | 深蓝背景、发光植物 | 信息有限、贫瘠、捕食者 | 感知、节能、快速通过、寻找补给 |
| 热泉圣所 | 暖黄与薄荷绿、开阔盆地 | 最后入口压力，内部稳定 | 用最终身体穿过入口并存活抵达 |

低温作为环境条件，可放在急流或洞穴中，不必新增一个区域。

最低版本把菌柱、急流、洞穴中的部分机制合并到一个挑战区。优先保证区域有实际空间和机制差异，再增加装饰。

### 9.2 知识锁与细胞分布

纤毛、吸收、膜在多处可获得，避免错过一次就无法通关。收缩、感知、传导有对应生态位，但不是唯一通关钥匙。

关卡应至少提供两种可行策略，例如逆流推进与借助侧路，或保温与快速穿过。它们是否真的成立必须通过不同身体的通关验证。

### 9.3 NPC 与捕食者

NPC 优先复用玩家细胞、连接和执行规则；行为控制器只决定何时激活线路。示范生物展示一种可观察的构筑，危险生物用接触伤害和追逐行为制造压力。

首版不做“吸收细胞天然能攻击玩家”的隐藏规则。若捕食需要伤害机制，明确由危险接触行为提供，并用动作、颜色和音效提示。

NPC 身体数量、细胞数量和营养颗粒总量均设置预算，避免玩家之外的模拟成本失控。

### 9.4 教学、失败与结局

教学只解释单细胞规则、输入和编辑操作。环境中的示范生命承担组合启发。

失败显示具体原因：核心损伤、长期缺能、过热等，并允许快速重开。整合建议在挑战区前提供恢复点，保存合法身体和基础资源，避免编辑失误迫使玩家重玩全部内容。

抵达圣所后降低环境噪声，展示最终身体并给出明确完成反馈。幼体延续动画属于可选表现。

## 10. 美术、界面与声音

### 10.1 统一视觉语言

关键词：卡通、果冻、海洋精灵、软、圆、透、亮。

使用圆、椭圆、水滴、花瓣、豆子与圆润壳片。避免真实眼球、细胞核、内脏、肉褶、密集细毛与恐怖深海表现。

《美术和程序相统一》中的 Eyes 图层理解为**可选卡通表情**；不要求每个细胞都有眼睛，也不恢复旧版真实眼球设计。

角色以低饱和浅青、奶蓝、淡紫等统一主色为基础，功能与激活状态使用局部强调色。环境共享轮廓、高光、柔光和阴影语言，降低对比，让玩家身体易识别。

### 10.2 模块资源

每种细胞一个 Prefab；源文件保留图层，运行资源优先透明 PNG。单体资源尺寸与像素密度统一，初始可在 256 或 512 像素方案中选择一套。

建议图层：Body_Base、Outline、Feature、Glow、可选表情、可选激活叠层。纤毛、花瓣和触角需要独立动画控制点。

为单体和融合状态定义不同显示规则。运行状态弱化内部轮廓，保留星点、条纹、光线和外露功能特征；编辑状态清晰展示所有节点和线路。

### 10.3 连续身体

先实现果冻桥和独立边界淡化，再验证动态连续膜。Metaball 或遮罩融合只负责连接自然，不吞掉全部形状，不填死圆环、开口或摄食通道。

纤毛、吸收花瓣、感知触角和膜片保留自身轮廓。外膜渲染是表现层，不能无意改变碰撞和流场规则。

### 10.4 信号与界面

建议通道色：W 蓝青、A 嫩绿、S 金黄、D 粉紫。颜色之外保留字母标识，编辑时不只靠颜色判断通道。

普通模式显示当前激活路径与局部响应；编辑模式显示完整线路、朝向、合力和转矩。持续输入用持续亮度和流动纹理表现，光点动画不意味着额外信号源。

游动界面只常驻四项资源、危险提示与目标方向。重组界面显示选中细胞的规则、通道、连接和旋转操作；不展示“推荐器官配方”。

### 10.5 声音与关键反馈

| 行为 | 反馈目标 |
| --- | --- |
| 同化完成 | 气泡、果冻桥、小幅弹动、轻柔啵声 |
| 摄食 | 光点进入吸收面、花瓣响应、轻短音效 |
| 收缩 | 实际缩短配合软弹动画 |
| 缺能 / 过热 | 与状态对应的清晰提示，避免持续刺耳 |
| 系统启动 | 光纹、稳定动作、节奏加入 |
| 圣所 | 危险提示退去，环境与音乐放松 |

## 11. 程序结构与实现边界

### 11.1 建议系统结构

```text
GameSession：开始、暂停、恢复、失败、胜利
Organism
├─ CellGraph：节点、连接、核心连通性
├─ SignalSystem：线路配置、衰减、活动强度
├─ PhysicsSystem：纤毛受力、连接、收缩、环境作用
├─ MetabolismSystem：共享营养、能量、温度与供给
├─ AssimilationSystem：接触、进度、接入
└─ EncapsulationSystem：可选编辑分组
World
├─ FlowField / TemperatureField
├─ NutrientSystem：生成、运动、吸收、数量预算
├─ CreatureSystem：NPC 身体与行为输入
├─ HazardSystem：碰撞、捕食、环境负荷
└─ GoalRegion：圣所抵达检测
Presentation
├─ CellVisual / BodyVisual / SignalVisual
└─ HUD / BuildEditor / AudioFeedback
```

### 11.2 核心数据

| 数据 | 用途 |
| --- | --- |
| CellDefinition | 类型、质量、连接数、能力与消耗参数 |
| CellNode | 实例、变换、局部完整度、连接与执行状态 |
| FusionLink | 两端、锚点、长度、强度、核心出口通道 |
| CellBehaviour | 各类细胞的独立行为 |
| CellVisualProfile | 图层、颜色、激活及融合显示规则 |
| OrganismState | 共享资源、启动统计、核心状态 |
| RegionDefinition | 流场、温度、生成预算与区域表现 |
| BuildSnapshot | 可选的恢复点身体数据；不序列化运行时物理组件 |

不提前实现复杂进化框架。可用简单参数修饰接口预留扩展，不让预留工作阻碍原型。

### 11.3 更新顺序建议

固定模拟步骤：读取输入与当前结构 → 求有效信号 → 汇总活动需求并分配能量 → 执行推力 / 收缩 / 环境作用 → 更新摄食、代谢、温度和损伤 → 处理脱落与同化 → 更新启动统计。

模拟顺序固定并记录，避免资源读写因节点遍历顺序而改变结果。表现层从模拟状态读取，不反向赠送资源或施力。

编辑与同化改变图时统一刷新连接关系、信号缓存、物理约束和视觉，不在各系统中分别维护不一致的身体副本。

### 11.4 工程落地顺序

创建工程并尽早打包空场景 → Cell Lab → 最小身体编辑 → 信号与受力 → 营养闭环 → 环境压力 → 关卡起终点 → NPC → 美术与声音。

建议目录分为 Scenes、Scripts、Data、Prefabs、Art、Audio、UI。先保持单工程、少量场景和清晰职责，不引入庞大框架。

### 12.1 三个止损节点

- **Day 3：**多刚体不稳定就切换方案，同时重新评估收缩，不继续无期限调 Joint。
- **Day 10：**三种结构效果和摄食闭环未成立，停止新增细胞、地图与 NPC，投入底层规则与反馈。
- **Day 15：**冻结功能。完整五区域未成形就合并为三段；封装、额外 NPC 与复杂膜按优先级延期。

Day 19～20 只处理完成度和阻断问题。赛事截止时间确认后，另设打包与上传缓冲。

## 13. 验证与提交标准

### 13.1 Cell Lab 验证环境

提供可重复的营养生成、恒定流、低温、障碍和危险开关；支持清空 / 重置，显示输入、合力、转矩、摄食量、活动消耗与净能量收益。

组合对照时保持细胞数量、初始资源、环境和观察时长相同，只改变布局、朝向或线路。调试无限资源可以用于观察物理，但不能用于证明生存闭环。

### 13.2 必须完成的验证

| 检查 | 通过条件 |
| --- | --- |
| 构筑有效性 | 移动、旋转、拆接后图与表现一致，退出编辑不产生异常冲量 |
| 信号 | 无线路不激活；断路后停止；环路不无限放大；多键不无限叠加 |
| 物理 | 目标规模持续施力和碰撞不出现不可恢复发散 |
| 涌现 | 三种结构效果有可重复对照，其中包含跨细胞协同 |
| 摄食闭环 | 主动摄食覆盖新增活动成本，能量不足与恢复可观察 |
| 生存 | 低温、过热和损伤有原因、反馈与恢复机会 |
| 关卡 | 至少两种不同身体或策略可从开局到终点 |
| 新手理解 | 未读文档的试玩者能完成第一次同化、布线和摄食 |
| 运行包 | 脱离编辑器启动；画面、输入、音频、重开与胜利正常 |

性能目标和最低测试机在工程建立后确认，记录帧时间、节点与颗粒预算。没有测试数据时不承诺具体帧率。

### 13.3 最终交付清单

- 一个从开始到失败 / 胜利都可运行的游戏包。
- 简短操作说明、版本号、必要的运行信息和已知问题。
- 清楚展示构筑、协同摄食和完整生命的截图 / 短视频。
- 项目源码与资源来源记录，保存赛事允许范围内的备份。
- 按赛事要求核对平台、AI 使用声明、素材许可、命名、上传大小与截止时间。

## 14. 风险、待确认项与决策记录

### 14.1 主要风险与处理

| 风险 | 预警信号 | 处理 |
| --- | --- | --- |
| 物理不稳定 | 链和环持续抖动、穿透、爆散 | Day 3 切换刚体方案，缩减柔性能力 |
| 流场只有外观 | 粒子漂亮但摄食量不提高 | 对照统计真实颗粒轨迹与净收益，先做定向滤食 |
| 膜无法导流 | 仅增加防护数值 | 实现实际阻挡；不成立就不计入涌现验收 |
| 编辑操作过重 | 首次布线需要反复解释 | 缩短操作步骤，明确选择、通道与方向反馈 |
| 开局卡死 | 核心无力靠近首个纤毛 | 安全湾、近距离细胞、基础维持或最小初始身体 |
| 正反馈不明显 | 只有资源条上涨 | 调供给连续性、流路与音画反馈，不靠启动 Buff |
| 内容拖慢交付 | Day 12 尚无完整起终点 | 用三段地图交付，延期扩展 |
| 视觉吞掉功能 | 身体成为无差异的一团 | 保留外露特征与开口，简化融合遮罩 |

### 14.2 待确认信息

2. 已安装 Unity 版本、开发机与计划测试机，是否已有可用美术或音频资源。

4. 更偏向自由构筑的深度，还是短局探索的完成度；当前排期优先保证完整可玩闭环。

这些信息不妨碍先做 Cell Lab，但会影响最终范围和提交流程。
